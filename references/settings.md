# 设置

设置页包含“录音留存”和“批注派发”两个真实分类。信息图标支持悬停、键盘聚焦及触控；删除后果、清理范围和自动派发的授权范围直接显示，不藏在提示中。

## 批注派发

`dispatch_mode` 默认为 `manual`。已有设置缺少该字段时按人工确认读取，不会改写原文件。用户在设置页明确选择并保存 `automatic` 后，会生成真实选择时间 `dispatch_consent.enabled_at` 和随机标识 `dispatch_consent.id`。模式含义是允许后续主动提交的明确任务发送到对应 Codex 会话，或在对应已核验项目中新建会话；宿主要求的用户授权和权限仍必须满足。

文字只在用户主动提交时绑定授权，并且提交的 `dispatch_opt_in` 必须与当时页面读取的模式标识一致。新增或修改的条目获得当次授权，未变化的旧条目保留原授权或无授权状态。口述捕获用户点击开始录制时的模式，在成功完成后绑定音视频文件；录制后才开启自动不会追溯授权这段口述。没有对应提交记录的既有材料不能自动派发。

关闭模式会撤销尚未领取批次的自动权限。重新开启产生新标识，旧授权失效；更改留存策略不会改变派发授权。已经领取但结果未知的批次仍需查目标核验，不能盲目重发。已发送回执保留，`sent` 只表示发送成功，不表示执行完成。自动模式不创建定时循环。

明确目标、完整任务和验收、无待答问题、高置信度以及有效输入绑定必须同时满足，否则仅该条目留在“自动派发结果”的待定区。用户可以在同一页面请求当前会话补充并转人工确认。没有派发尝试时，可将本轮转成人工；已有尝试时，只把待定项带入新一轮，保持旧回执不变。

## 录音留存

看板顶部的“设置”提供全局录音留存策略。设置保存到 `~/.2hours/settings.json`，默认一直保留。候选策略为处理并完成审核后、1 天、2 天、1 周、1 个月（30 天）。时间从文件最后修改时刻计算，设置页显示每个文件的具体到期时间。

保存策略不删除文件。当前版本没有后台定时清理；用户在同一设置页检查明细后，点击明确列出数量和大小的删除按钮，才执行清理。页面刷新预览时也不删除文件。

清理只覆盖 `~/.2hours/runs/*/blurt/` 内的 `recording.mp4`、`audio.wav` 和 `video.mkv`。自定义运行目录、其他项目、截图、转写、报告和审核记录均不在范围内。符号链接、硬链接、非普通文件和无法核验的目录受到保护。

材料必须已经形成有效的 `blurt/items.json` 并完成录音审核。支持旧版 `reviewed: true` 和当前与冻结来源相符的 `review-confirmation.json`。卡片“已审阅”仅表示阅读状态，不满足录音审核条件，也不批准分发。正在录制、未处理、未审核、音视频比处理结果更新、审核依据已变化或状态无法核验时，文件均不会删除。

接口沿用本地桥的同源和 token 校验。`GET /settings` 返回设置、范围、到期明细与预览标识；`POST /settings` 接收 `retention` 或 `dispatch_mode` 及当前 `revision`，保留其他设置；`POST /cleanup` 只接收当前 `preview_id`，不接受调用方提供的文件路径。清理持有全局设置锁和相应运行的分发锁，逐层以 `O_NOFOLLOW` 打开父目录，在移动前及移动后再次核验审核与录制状态。

文件先原子移入该运行内唯一的 `.retention-recovery-*` 目录。移入文件与预览的设备、inode、大小和修改时间一致且仍符合保护条件，才会删除。变化或错误发生时，文件保留在恢复目录，页面显示完整恢复位置；不会覆盖式移回原路径。恢复目录不参与后续自动预览或清理。恢复时先检查原位置是否已有新录音，避免覆盖新内容。

验证命令为 `python3 -m unittest tests.test_settings tests.test_bridge tests.test_dispatch -v`。清理与自动派发验证仅使用临时夹具，不调用真实发送工具。
