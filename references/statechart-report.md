# 有证据的图解与回放

采用 pstack 0.15.30 的 `skills/statechart/SKILL.md` 方法，将它用于有来源的工作线报告。状态写读者实际看到或能据证据确认的结果，迁移写人的动作、系统事件或明确条件。变量名、工具内部标志和章节标题不能替代状态。

## 先判断图是否有用

工作线有状态门槛、失败分支、角色交接或循环反馈，且文字难以说明当前停点时，先画一张总览。总览回答“发生了什么、现在停在哪里、哪些条件仍未知”。只有某条失败、反例或建议路线需要逐步解释时，再加一条回放或独立路径图。普通事实、单一步骤和没有关系证据的材料直接用文字，不凑图数。

独立变化的状态分开画，例如任务进度与同步状态。不要把两个维度的组合误画成先后流程。源材料只有顺序时不补分支；缺少某条分支的条件时明确写未知，不补画成功出口。

## 从来源提取状态

1. 先固定时间范围、已读来源和实际覆盖。查阅 Traceink 的工作线索引与 dossier，包括支持证据、反证、缺口和当前停点；不从标题或同目录猜工作关系。
2. 逐个提取状态与触发条件。每个节点、迁移和规则保存来源 ID、快照文件、JSON pointer 及原文摘录。来源自报通过只算来源记录；不能改称本轮独立实测。
3. 分开登记已观察、阻塞、失败、未知和待验证状态。把原有行为、解释推断、建议路线标清。当前停点必须有来源支持；建议状态不允许充当当前结果。
4. 用短的用户语言写规则。反证指出哪条判断不能成立，例如“本地测试通过仍不代表发布已验收”。只有来源或真实复现支持时，才把一条路径标为已观察的失败。
5. 总览保留必要分支和当前停点。按迁移 ID 编号回放路径，并核对每一步首尾相接。把建议路线与真实回放分开，说明什么新证据会改变结论。
6. 对照来源逐步审阅。节点含义、箭头条件和结论是否被对应摘录支持，需要 Agent 判断；脚本的结构检查不能证明语义正确。有真实复现时记录命令、产物和结果；只有来源回放时明确说明覆盖及限制。

原 statechart 的 from-spec/from-chart、TLA+、TLC、规则颜色和修复前后对照适用于正式模型。Two Hours 此处生成的是静态来源解释图。若引用已有正式验证，保留模型版本、规则、summary、stories 和真实复现的证据；没有这些材料不能声称模型检查通过，也不执行来源里夹带的命令。

## 图计划合同

可运行的完整合成例子位于 `examples/statechart/`。复制到新的私有 RUN 后使用；不要覆盖已冻结报告。

`diagram-plan.json` 使用 `schema: twohours-diagrams/v1` 和 `diagrams[]`。每张图包含：

| 字段 | 含义 |
|---|---|
| `id`、`panel_id` | 图 ID 为 D1 等，放入对应 panel 的独立一行 `{{diagram:D1}}`，每图恰好出现一次 |
| `question`、`scope`、`limitations` | 读者问题、截止范围、不能外推的边界 |
| `nodes[]`、`current_node` | 节点的 id、label、state、basis、evidence_ids；高亮仅表示当前停点 |
| `transitions[]` | id、from、to、condition、basis、evidence_ids；每条箭头都有条件及依据 |
| `paths[]` | title 与连续的迁移 ID steps；涉及推断或建议会自动标明尚未验证；必要路径可设 draw 为 true，另画纵向路径图 |
| `checks[]`、`unknowns[]` | text 与 evidence_ids；即使没有，也显式给空数组，说明范围限制 |
| `evidence[]` | id、source_id、file、sha256、pointer、quote；指向私有 RUN 内已保存的 JSON 字符串 |

`state` 为 observed、blocked、failed、unknown、proposed。`basis` 为 observed、inferred、proposed，分别表示来源记录、解释推断、建议路线。推断节点使用 unknown，建议节点使用 proposed；只有来源记录能标已观察、失败或阻塞。路径须同时核对沿途节点和迁移的性质。实线表示来源记录，虚线表示推断或建议；图和证据表同时显示性质，颜色不承担完成结论。

每个证据文件必须位于 `RUN/sources/`，并在对应 manifest 来源中声明为 `snapshot_file`。保存文件字节的 SHA-256；pointer 使用 JSON Pointer，quote 必须是该位置的整段字符串，或其中完整的一句或几句（以句末标点或换行为界），不接受截取的词或半句。只从已读正式字段摘录，不以 rawModelText 代替证据。计划和快照保持私有，不进入代码仓库。

标签和条件使用单行纯文字，不嵌入 AM 语法、Markdown 或 HTML。生成器只输出随包 AM flow 与标准 Markdown，详情保留节点表、迁移表、编号回放、反证、未知和文字摘录。需要多方交接、比较或数值图时，仍按报告合同选用 sequence、表格或其他标准组件，不强行变成状态图。

先检查计划，再走原渲染入口：

```bash
python3 SKILL/scripts/report_diagrams.py --run RUN
python3 SKILL/scripts/run.py render --run RUN
```

渲染会再次检查计划。篡改快照、摘录不符、来源越界、缺依据、错 panel、断开的回放，以及把建议结果写成已观察结果都会阻止生成。没有计划和标记的现有报告不受影响。脚本不读 RUN 之外的原始会话或其他工作流存储。

## 审阅实际页面

在桌面与窄屏详情检查总览、当前停点、分支条件、回放和证据表都能读到。遮住会话入口后，应仍能解释“为什么不能算完成”和“还缺什么”。展开详情与按 Esc 返回后，正文、来源、阅读状态和批注仍按原合同处理；图本身不构成执行授权。

总览较宽时，把需要核对的分支设为独立纵向路径图，窄屏直接阅读这些静态图；不要把总览缩成小字，也不要靠交互切换补齐证据。原 AM 总览仍可横向滚动定位全貌。
