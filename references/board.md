# 看板与文字批注

`board.json` 是当次报告的目录摘要，不放在技能代码中。其 ID 与 manifest / AM 面板一致；正文仍由 AM 渲染，构建脚本保留图表、表格和来源。每次运行只需写数据。

```json
{
  "title": "先把注意力放在需要判断的地方。",
  "subtitle": "阅读一份，判断一份。文字意见与口述批注，在这里汇总。",
  "period_label": "本次回看范围",
  "review_label": "本次审阅日期",
  "coverage_label": "实际读取的会话与消息数量",
  "cards": [
    {"id":"A1", "lane":"decide", "label":"实验",
     "title":"需要选择的具体问题", "value":"2", "unit":"个方案",
     "state":"预算待定", "context":"报告范围与关键限制"}
  ]
}
```

`decide` / `follow` / `result` 分别是需要判断、继续跟进、结果与来源。每列最多 3 张，总数最多 8 张；报告信息便利贴放在首屏右上方，不占用卡片位置。内容更多时按工作线合并卡片，详情保留证据，不丢掉材料来凑数量。构建会校验所有 ID、数量与分组；标题和摘要转义，面板中禁止脚本与内联事件。

正常入口为 `run.py render --run RUN`，发现 board.json 后自动把 AM 产物保存为 report.am.html，并生成最终 report.html。已有受检 AM 内容也可先存为 report.am.html，调用 `build_board.py --run RUN`。已有 report.html 不允许覆盖，换版需新建运行，旧录音、批准与回执不搬成新指令。

## 审阅状态

- 每卡的 `read`、`comment` 与 `revision` 写入 `review-state.json`，重开页面可恢复。
- “标记已审阅”是明确动作，打开窗口本身不算读完。待审阅卡片显示曲别针。
- “保存意见”只持久化。未保存输入有浏览器草稿与关闭提醒，保存失败不清空输入。
- 同一卡片另一页面已更新时，旧 revision 被拒绝，用户可先复制当前文本再刷新核对。

## 提交与分发

“批注与分发”显示已保存意见。用户点击“提交文字意见”时，服务校验展示版本，将原话、panel ID 与标题写入 `written-items.json`，并输出 `comments_submitted` 事件。重复提交相同内容不会制造重复事件。

宿主收到事件后逐项理解，和口述合并成统一审核草案。保存或提交不直接向任何会话发送消息。新提交会让旧草案失效，必须重新 prepare-review；已有最终确认后，新增意见用下一轮运行处理，不能覆盖已批准快照。

`dispatch.py prepare-review` 可消费纯文字、纯口述或两者。未审核口述可以用于草案，不能直接派发；只保存但未提交的文字不进入草案。统一审核页用任务目录与单份编辑区展示原话、证据、理解和去向，底部只有一次最终确认。草稿按 review_id 保留，材料变化时不静默套用旧编辑。
