# 报告内容合同

报告服务于集中理解与判断。读者只看一张卡的详情，就应知道这项工作是什么、为什么值得注意、目前做到哪一步、证据能支持什么，以及下一步是否需要自己决定。原会话入口用于追溯，不承担补齐正文的职责。保留既定的一屏概览、独立详情和统一审核。Agent 工作与 Cubox 阅读分区呈现，卡片数量按实际材料决定，不固定为 3／3／2 或 8 张。

## 从来源写成可判断的卡片

先整理已读证据，再写结论。按实际问题组织下列内容，可合并短节，不为凑格式增加空话。

| 读者需要知道 | 正文应交代 |
|---|---|
| 这是什么，为什么现在看 | 项目或对象的用途、用户原目标、本次触发问题，以及读懂后文所需的背景。首次出现的关键术语就地解释。回应具体批注时保留必要原话。 |
| 当前该如何理解 | 开头给结论和重要限制。区分原有基线、本期变化和截止时刻状态；已结束、已批准与待办不能混写。 |
| 怎样运作，变化在哪里 | 说明参与者、输入、关键步骤与输出。研究卡说明任务、方法、条件和指标含义；流程卡说明控制流、交接和停止边界。 |
| 为什么相信，哪里仍未知 | 给直接证据和来源定位，区分实测、来源自报、作者观点、用户意见与 Agent 推断。保留失败、反例、未测项及其对结论的影响。 |
| 下一步怎么选 | 先给有依据的建议。存在真实取舍时比较收益、代价、前提与不做的影响；只把用户的目标、预算或授权选择留待判断。无需决定的卡直接说明当前状态。 |

“信息充分”不等于粘贴整个会话。优先保留会改变判断的约束、证据和选项，删掉重复过程叙述。短结论可以很短；复杂流程不能压成几句状态播报。

研究卡尤其要区分工程检查与方法效果、开发条件与未见场景、合法安全退出与任务完成。数字写清版本、分母、单位和条件；不同协议或含义的数值不合成一张可比图，不以未测代替零分。没有证据时明确缺口，不填造背景或推荐理由。

## 阅读卡直接呈现文章

阅读区按文章或有真实共同主题的文章组织，先给内容摘要，再列作者论点、关键证据、用户标注和原文入口。没有标注就明确说明没有，不补写虚构引用。正文不可读时标明 `metadata_only` 及原因，不把标题推断冒充全文摘要。

抓取成功、整理了几篇、已传给 Agent 等处理过程不构成阅读卡的核心内容。与已有工作的关系可单独写为推断；除非已有真实授权，不能把文章结论改写为待执行任务。独立的工作进展与决策留在工作区。每篇原文和其来源 ID 仍须可追溯。

### 按文章主题检索个人知识

Cubox 阅读先理解文章，再查用户指定的知识库。用户仅说“知识库”时，沿用全局配置的 LLM-Wiki 路径；先读根 `AGENTS.md` 和 `.agents/skills/llm-wiki/SKILL.md`，按查询流程只读检索。阅读报告不授权 ingest、修改索引或日志、改写 Skill。

1. 从已读正文提取研究对象、核心机制和适用场景，形成主题词及同义词。不要把 Two Hours、当前仓库或收集工具作为默认搜索词。
2. 用 `rg` 搜索 `wiki/` 的相关概念、来源、综合与比较页，再读候选页面正文和证据边界。只看到标题、标签、搜索摘要或索引，不能宣称知识关联已验证。同步冲突副本与历史日志不替代权威页。
3. 保留真正帮助理解本文的关联，说明共同点、差异和不可互推之处。文章事实、Wiki 已有结论、Agent 新推断分别标明；同名框架不等于同一实现，机制相似不证明效果等同。
4. 在阅读卡中引用条目名称、绝对路径、已读行号或章节，并将本地来源登记到 manifest。私有 RUN 留下主题词、检索范围、采用与未采用理由、读取时间；补读知识属于本次解释材料，不倒写为回看时段的工程成果。

只选与文章主题有直接关系的少量条目，不固定要求数量。无相关条目就说明检索范围与缺口，不强行联想。知识库不可访问时保留文章摘要并报告限制。只有文章本身与 Two Hours 存在具体关系且有已读证据时，才写这种关联；“由 Two Hours 收集”不是依据。

## 主动选图，不等用户要求

写每张卡时先明确读者要回答的问题，再选表示。流程、关系、状态变化或多维比较通常需要图或表，普通短事实无需强行配图。采用 ctx-report 的问题拆分、先证据后结论和有依据的建议；采用 answer-me-with-html 的按信息结构选组件。只吸收报告方法，不启用 ctx 存储、归档或蒸馏流程。

复杂卡有多个真实子问题时，可用 `tree` 给出问题地图；叶子写读者的问题，不重复章节名。只有一个问题时用一句话交代。每张图只回答一个问题，图前说明问题，图后说明来源与解释边界。

| 内容形状 | 使用随包 AM 的表示 | 需要保留的信息 |
|---|---|---|
| 顺序过程 | `flow` | 输入、动作与输出。来源确实只有顺序关系时保留线性图，不人为加分支。 |
| 分支、授权或状态门槛 | `flow` | 判断节点、每条分支的条件、失败或未知出口、通过后能声明的状态。把当前停点与建议验收分开。 |
| 多方交接、请求与回执 | `sequence` | 谁发送什么、谁执行、谁返回什么证据；区分已请求、已送达、已执行与已验收。缺少回执时显式标缺口，不补画成功响应。 |
| 因果解释与故障定位 | `flow` 配证据表 | 区分观测、已复现机制和待证假设。箭头写作用机制或条件，表格给反例及替代解释；时间先后不自动构成因果。 |
| 任务内与跨任务的双层循环 | 分开的 `flow` 或分组 `flow` | 两层各自的对象、输入、反馈、输出与停止条件，以及跨层传递的经验和证据。画回到哪里，不能把循环压成一次性流水线。来源未交代门槛时标未知，不自创成功规则。 |
| 版本或阶段演进 | `timeline` | 时间、版本和状态，阶段结果不混为最新结果。 |
| 能力关系、模块归属 | `tree` 或 `flow` | 关系类型与范围，箭头不暗示未经证实的因果。 |
| 多维取舍、证据强弱 | Markdown 表格 | 同一比较维度下的收益、成本、前提与证据强度；缺资料写未知。建议说明取舍依据，不靠箭头或颜色给未验证方案排胜负。 |
| 同口径实测数值 | `chart` 或 `limits` | 分母、单位、版本、来源与完整失败项；没有真实数据就不用数值图。 |

使用 AM 标准组件，由 renderer 生成静态 SVG。不要手写 HTML/SVG、加入 Mermaid/CDN 或文件 inclusion。Two Hours 构建只保留静态正文，不依赖 AM 页面的运行时交互；不要使用 `ask`、Before/After 切换或需要脚本的控件代替正文和统一审核。需要解释改动时用静态图注、时间线或比较表。

图的节点与连线必须能对应已读来源。若是 Agent 综合或建议，图注明示，并保留支持它的事实；不能把推断升级为已验证状态。宽图优先缩短节点、拆成两个有各自问题的小图或改用纵向布局，不靠把字号压小容纳信息。表格给图示补充例外与证据，不逐字重复图中全部节点。

绘图前在私有 RUN 记录“问题、表示、来源定位、事实或推断、当前状态、未知条件”。区分来源原有机制和 Agent 为解释提出的验收路线。图示增加的判断信息应具体可指出，例如为什么不能算完成、失败后去哪里、由谁接棒、哪条证据会改变建议。只有更换节点外观或把段落拆成串联框，不算改善。

## 溯源与交付检查

每个关键结论、图示和数字旁写来源 ID 与精确定位。卡片末尾集中列出来源名称、会话/原文入口、实际读到的时间或行号、必要产物的绝对路径。只引用 manifest 已登记来源；补读材料先登记，再用于正文。一个跨会话卡片可有多个来源，不把执行去向当成唯一来源。

渲染后检查实际页面，不只看 Markdown。

- 遮住原会话链接后，读者仍能回答本卡的背景、变化、证据边界和下一步；检查术语、数字分母和推荐理由是否缺失。
- 流程与研究判断卡优先抽查。图已渲染，节点、箭头、图注与来源对应；原始数据表和来源仍可读。无证据的卡不为了达成图数量而画图。
- 分支图检查条件与出口是否齐全，状态图检查未知是否误写成失败或成功，交接图检查是否伪造回执，因果图检查是否把相关当成因果，比较表检查口径是否一致，双层图检查任务内反馈与跨任务反馈是否都可见。若来源缺少停止条件，正文必须保留该缺口。
- 阅读关联检查主题词是否来自正文、条目正文是否已读、引用能否定位、推断是否单列。用不同主题的阅读夹具验证关联会随文章改变；允许无命中，不允许统一落到 Two Hours 开发。
- 所有 panel ID 与 manifest、board 一致。常用桌面尺寸首屏显示区域、全量数量和当前页，不长滚动；较多材料可逐页到达，窄屏可切换阅读与工作，少量和空区不强凑卡片。长正文在详情内滚动，图表与来源不被裁切，关闭后返回原卡片。
- 报告与图示本身不授权派发。授权来自人工集中确认，或用户显式选择自动模式后提交的明确任务；目标不明确的条目单独待澄清。已冻结报告需要修订时，在独立预览或新运行生成，不覆盖原报告、录音、条目或批准。

`examples/review/report.md` 中 A1 展示研究判断，A6 展示带分支的流程。示例全为虚构数据；真实报告与检查截图留在私有运行或预览目录，不写入技能仓库。
